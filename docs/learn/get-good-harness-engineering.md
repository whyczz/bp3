# Measured loops that kept the code

**Question.** People who actually build harnesses: what loop have they run, what did they measure, what did they kill, and which of that is a reason to change backpack? One quest here takes about half a day. The author-subagent, grader-subagent, and conductor loop burns tokens and time. The loop that still makes progress is induct-inline: the main session writes the code, and a fresh subagent grades. Sometimes one ordinary prompted session would have been faster.

**Reader.** The owner of bp3.

**Fetched.** 2026-11-23. Primary pages and repos were opened that day. The notes are [builders.md](/Users/whycz/m/bp3/research_notes/Harness%20engineering%20that%20ships/builders.md), [forums.md](/Users/whycz/m/bp3/research_notes/Harness%20engineering%20that%20ships/forums.md), [github.md](/Users/whycz/m/bp3/research_notes/Harness%20engineering%20that%20ships/github.md), and [backpack.md](/Users/whycz/m/bp3/research_notes/Harness%20engineering%20that%20ships/backpack.md). An older dossier, [agent-harness-landscape.md](/Users/whycz/m/bp3/docs/dossiers/agent-harness-landscape.md), was compiled 2026-11-19 (sixth pass 2026-11-20), and [CONTEXT.md](/Users/whycz/m/bp3/CONTEXT.md) was checked 2026-11-19 and 2026-11-20. Neither is fresh evidence. This report does not carry their claims forward unless the new notes restated the claim from a file read on this pass. Where a CONTEXT.md sentence is only in CONTEXT.md, it is left out or marked not re-checked.

**How to read.** The detailed findings are the evidence, in prose, with links. Then a distillation of about two pages: which loop shapes have a measured result, which have a manifesto, and what the runs that kept something have in common. Then backpack as it runs, including the commits. Then proposals. The proposals are not a verdict and not a design to build. Last, what this pass did not verify.

A figure is measured only when the person reports a count from their own run. Lab posts are tagged. A number from a recap, a chart this pass could not read, or a comment that does not link an artifact is fenced. Stars are not proof. If two notes disagree, both numbers are here.

## Builders who shipped, and the numbers they published

The 2026 posts did not collapse practice into one harness. Four shapes are still in print. Geoffrey Huntley runs one fresh-context process, one task, and a check the model cannot talk past. Mario Zechner, and Armin Ronacher when he means to keep the code, run one small coding agent in one session with a human still steering. Peter Steinberger, and Mitchell Hashimoto with a single background agent, run several top-level sessions and stay the only coordinator. The lab and product harnesses (OpenAI's Codex repository, Cognition's Devin, Steve Yegge's Gas Town) put a coordinator, a clean-context reviewer, or a tracker in front of workers, and some of them take the human off the merge. The individual builders who still like the code did not ([builders.md](/Users/whycz/m/bp3/research_notes/Harness%20engineering%20that%20ships/builders.md)).

### Huntley

Ralph, post dated 2025-07-14, is a search extract on this pass: the full fetch of the page returned only the title, and the quotes below are from that extract. In its purest form Ralph is `while :; do cat PROMPT.md | claude-code ; done`. It "works autonomously in a single repository as a single process that performs one task per loop." He calls the technique "deterministically bad in an undeterministic world." No coordinator and no role-played workers ([Ralph](https://ghuntley.com/ralph/)). On 2026-11-11 he wrote that the way to stop a loop closing on bad output is deterministic checks, that those checks are not skills, and that his loops run as root inside a throwaway Nix machine so the agent can inspect the database and journals. He would not do that on Ubuntu. He says his loop style is very different from Steve's ([the answer to ai is engineering](https://ghuntley.com/answer/)). The 2026-03-15 porting recipe is two loops that write specs, one from tests and one from `src/` with citations back to the source, then "a classic ralph" that does one thing per loop against a strict compiler on the target language ([porting](https://ghuntley.com/porting/)).

On 2025-12-29 he said Ralph existed as an unreleased first-class harness called Loom: self-hosted, alloying models, tight source control, no human steering, remote async jobs, the IDE only as a crash cart. That post has no ship date and no usage count ([Loom tweet](https://x.com/GeoffreyHuntley/status/2005548106797207766)). The **$10.42 an hour** figure is not a worksheet in either page this pass opened. On 2026-02-27 he states it; on 2026-10-16 he attributes the calculation to Dex ([real](https://ghuntley.com/real/), [toronto](https://ghuntley.com/toronto/)). A reader email on the 2026-10-09 page, "delivering paid for dev worth 100K + for 3K in sonnet tokens" and re-platforming stacks in about two weeks, is anonymous and is not Huntley's result ([replaced](https://ghuntley.com/replaced/)).

### Zechner

Pi, 2025-11-30. He ships his own coding agent because Claude Code had become a spaceship whose prompt and tools change every release. What he kept: a system prompt plus four tools (`read`, `write`, `edit`, `bash`) **below 1000 tokens**, YOLO by default, no to-do tool, no plan mode, no MCP, no background bash, no sub-agent tool. Plans, if any, are a markdown file. `AGENTS.md` is the only injected context. He says the pi-ai library has been used in **seven production projects**. The projects are not named ([pi](https://www.mariozechner.at/posts/2025-11-30-pi-coding-agent/)). The same refusals are restated on 2025-12-22, where Clawdis is Peter's agent built on pi, not pi's orchestrator ([year in review](https://mariozechner.at/posts/2025-12-22-year-in-review-2025/)), and on the 2026-01-27 Vienna slides ([slides](https://mariozechner.at/uploads/2026-01-27-agents-anonymous-vienna/)).

On subagents, same 2025-11-30 post: spawning several of them to implement features in parallel "doesn't work, unless you don't care if your codebase devolves into a pile of garbage." If context is needed, gather it in its own session and write an artifact for a fresh session. He has spawned pi via bash for a review, and says that in practice he would just open a new pi session. The tool-list tax he quotes is text, not a chart: Playwright MCP, **21 tools, 13.7k tokens**; Chrome DevTools MCP, **26 tools, 18k tokens**; **7–9% of the window gone before work starts**. He ran Terminal-Bench 2.0, five trials, Claude Opus 4.5, and published a leaderboard image dated in the post as of 2025-12-02. The scores are in the image. This pass could not read them. No placement and no percent from that image belong in a later citation ([pi](https://www.mariozechner.at/posts/2025-11-30-pi-coding-agent/)).

### Ronacher

Two loops, 2026-06-23. One is the tool loop inside the agent. The other is a harness loop outside it that decides whether that was actually the end, by continuing the session, starting a fresh one, or sending the task elsewhere. He credits Ralph. He has not had much success with this way of working for code he deeply cares about, and he does not want Pi to become an uncontrolled swarm ([The Coming Loop](https://lucumr.pocoo.org/2026/6/23/the-coming-loop/)). The same post says models produce code that is too defensive, too complex, and too local, and that if each iteration adds another small defense the system becomes less understandable while looking more robust. The more hands-off the run, the more that happens. Claude Code with Fable, uninterrupted for thirty minutes or more, produces worse code by his taste than the more human-in-the-loop process of the previous autumn. That is not a scored eval. What he says the loop is good at: porting, performance search, security scanning, research, and artifacts that do not have to last. He also writes that many successful loops use another LLM as a judge or an orchestrator, because the harness only needs a signal to continue, and that signal does not have to be objective. He does not say the signal is good enough to merge lasting code ([The Coming Loop](https://lucumr.pocoo.org/2026/6/23/the-coming-loop/)).

The run he published and kept is the MiniJinja port to Go, 2026-01-14. One pi session, voice prompts, Opus 4.5 and then GPT-5.2 Codex, the existing Rust snapshot suite as the oracle, and pi's branch switch instead of a new coordinator. Pull request [854](https://github.com/mitsuhiko/minijinja/pull/854). His counts: **agent run 10 hours, of which 3 were supervised; active human time about 45 minutes; 2,698 messages; 34 prompts of his; 1,386 tool calls; $60 raw API; 2.2 million tokens**. Docstrings and small fixups are excluded. The agent gave up on the must-fail tests because error strings would not match, and it wanted to regress HTML escaping and `range` returning an iterator. He kept the port only after steering those. The design change he let stand, because it fit Go, was a tree-walking interpreter and reflection instead of his Rust bytecode interpreter ([MiniJinja port](https://lucumr.pocoo.org/2026/1/14/minijinja-go-port/)).

The run he published and killed is Astra, 2026-09-07. He turned the factory off after **35 hours**. Net addition **75k lines**. **About 1 billion tokens** and **about $1,200** raw API. **79 commits**, about **$15.50 per commit**, about **1,400 messages**. Earlier in the same post, a different estimate: the weekend burned a full reset's worth of ChatGPT tokens, **around 4 billion**. He does not reconcile 4 billion and 1 billion. Treat 1 billion, $1,200, 79 commits, and 75k lines as the run log, and 4 billion as his guess at what a subscription reset contains. He says the run delivered absolutely nothing of value. The setup was a model free to manage its own context, notes in `agent-notes/`, and subagents. Task ids decayed, Python was code-golfed into the edit tool, and constants showed up that do not match the codebase. He writes that he does not need an agent to run 35 hours on a single prompt, and that subagents are where the agent believes nobody is looking. The same failure, he says, shows up in ordinary Astra sessions, not only in the factory ([Astra](https://lucumr.pocoo.org/2026/9/7/astra-why/)).

"Building Pi With Pi," 2026-05-24, was a search extract, not a full read. They use Pi to build Pi. Parallelism is mostly for reproducing issues. A committed prompt, `/is`, tells the agent not to trust the analysis in the issue and to derive its own diagnosis from the code ([Building Pi With Pi](https://lucumr.pocoo.org/2026/5/24/pi-oss/)). Codemode, 2026-10-06, is a context firewall for tools, not a worker swarm: Pi 1.0 runs model-written code in QuickJS inside WASM, with no network, no file system, no timers, and limited RAM, and the only effect is to call more tools ([What is Codemode](https://lucumr.pocoo.org/2026/10/6/codemode/)).

A conference description, not his blog and not a transcript, is secondhand. The AI Engineer YouTube description posted 2026-11-22 says his session data shows tasks running **14 minutes instead of two and a half**, and **141 projects started with only 10 to 15 kept alive** ([YouTube](https://www.youtube.com/watch?v=JNexz3Tbiu8)). A same-day BigGo recap adds prompt counts and a P90. Those extra figures are the recap. They are not used below.

### Steinberger

"Just talk to it" has no publication date in the extracted HTML. The post links X posts from October 2025. It was fetched 2026-11-23. He says agentic engineering writes pretty much all of his code. The shape: Codex CLI, **between 3 and 8 in parallel**, in a 3×3 grid, most of them in the same folder. He experimented with worktrees and pull requests and always came back. Agents make their own atomic commits. He is the coordinator. He tells subagents to get lost and uses another window. The product he names is about **300k lines** of TypeScript React, plus a Chrome extension, a CLI, a Tauri client, and an Expo mobile app, on Vercel ([just talk to it](https://steipete.me/posts/just-talk-to-it)).

Costs he will stand behind only roughly: **four OpenAI subscriptions and one Anthropic subscription, around $1k a month**. API billing would be around 10×, and he says not to nail him on the math even if it is only 5×. **Five to ten times is his uncertainty band, not a bill**, and it is subscription versus API, not swarm versus one agent. At least half his prompts contain a screenshot. About 20% of his time is refactoring, as its own phase, not as a grader on every commit. `Agents.md` is about **800 lines**, written by Codex, a log of misses he says he should clean up. He deleted Tailwind 4 guidance once the models already knew it. That is not a claim that 800 lines is optimal. GitHub MCP at **23k tokens**, and almost **50,000** when it first launched, is a tool-list tax. The 230k versus 156k figures in that post are vendor window sizes, not a measurement of his sessions ([just talk to it](https://steipete.me/posts/just-talk-to-it)).

On role-play he is blunt: telling the model it is an AI engineer specializing in production-grade LLM applications will not change that. He calls that file an amalgamation of slop and context poison, and says not to waste time on RAG, subagents, and "Agents 2.0." A fresh context for the plan would easily add **10 minutes** of the model rereading files, and he stopped doing that once he moved to GPT-5. If something takes longer than he anticipated, he hits escape. File changes are atomic, so stopping mid-run is safe. Tests are written in the same context, after each feature, not by a second model. `/review` is only sometimes, because he has review bots on GitHub. Conductor, Terragon, Sculptor, and other harnesses did not stick. Among web agents, only Codex web stuck, and only as a phone-side scratch pad he reviews later on the Mac ([just talk to it](https://steipete.me/posts/just-talk-to-it)).

### Hashimoto

Hand-written, 2026-02-05. This is a Ghostty-era workflow, not a productized harness. An agent with read, exec, and HTTP. Tasks split across sessions. Planning separate from execution. A verifier. **One background agent, not many.** He is not running multiple agents and does not really want to. The background agent meets its goal **maybe 10 to 20% of a normal working day**. Amp's deep mode, which he says is basically GPT-5.2-Codex, can take **upwards of 30 minutes**. No token total, no pull-request rate, and no fraction of diffs kept ([My AI Adoption Journey](https://mitchellh.com/writing/my-ai-adoption-journey)).

The rule he kept: when an agent makes a mistake, engineer it so the agent never makes that mistake again, either a line in `AGENTS.md` or a real tool. He points at Ghostty `src/inspector/AGENTS.md`, where each line is based on a bad agent behavior. The surest path to a first-try result, he writes, is a fast tool that tells the agent when it is wrong. He does not add a model grader. He refuses to run agents for the sake of running them, and he turns notifications off so the agent cannot interrupt him. One agent, checked on his breaks ([Hashimoto](https://mitchellh.com/writing/my-ai-adoption-journey)).

### Cognition, lab

Walden Yan, "Don't Build Multi-Agents," blog index date 2025-06-12. The principles are from their own trial and error, not a paraphrase of a lab post they are summarizing. The default is one linear agent. Subagents answer a question. They do not write code in parallel, and the parent does not work in parallel with them. A second model may compress history; they say they have fine-tuned a smaller model for that. Parallel writers are fragile because actions carry implicit decisions. "You are a senior software engineer" and "think for longer" are gimmicks ([Don't Build Multi-Agents](https://cognition.com/blog/dont-build-multi-agents)).

The 2026-04-22 follow-up does not walk that back for writers. Parallel-writer swarms still do not see meaningful adoption. What he says works is several agents contributing intelligence while **writes stay single-threaded**. The shapes: Devin Review in a clean context, looped with the author; a "smart friend" tool the primary model calls; a manager Devin that splits work to child Devins over an internal MCP. Read-only subagents mostly resemble tool calls. The unstructured swarm is mostly a distraction. Their reviewer, on pull requests including ones Devin wrote, **catches an average of 2 bugs per pull request, of which roughly 58% are severe** (logic, missing edge cases, security). Enterprise usage in their most cautious segment is an **~8×** "explosion" over six months. The 8× sits next to a chart this pass did not read. The figure is in the prose. The review agent looks only at the diff and re-discovers any context it needs, because the author has been working for hours and context rot makes it a worse judge of its own work. The loop is not always great, because it can take a while. The author is then prompted to filter the reviewer's bugs against the user's instructions. Most bugs are already resolved by the time a human opens the pull request. **No token ratio of review to generation is in the post.** A cheap primary model (SWE-1.5) against Sonnet 4.5 was not good enough: the cost and speed wins were real, and the quality ceiling was the primary's, at knowing when to escalate and what to ask. Cross-frontier "smart friend" (Claude and GPT) produced gains on the trickiest cases. Manager Devins took more context engineering than expected. Managers default to being overly prescriptive, agents assume they share state with their children, and cross-agent communication does not happen by default ([Multi-Agents: What's Actually Working](https://cognition.com/blog/multi-agents-working)).

The same post points at Cursor's web browser (200k lines), Anthropic's C compiler (100k lines), and Karpathy's autoresearch (10k+ iterations) as demos that share a property most real software does not: a simple, verifiable success criterion. Those sizes are Yan's citations of other posts. The underlying posts were not opened. They are not Cognition measurements ([Multi-Agents](https://cognition.com/blog/multi-agents-working)).

Other Cognition numbers are search extracts, and they are lab. "Devin can now Manage Devins," 2026-03-19: a coordinator assigns scoped pieces to managed Devins, each in its own VM, because one session accumulates context and the quality of each subtask suffers ([Devin can now Manage Devins](https://cognition.ai/blog/devin-can-now-manage-devins)). Devin 2.1, 2025-05-15: green scores, **twice the likelihood of a merged pull request** versus red. They report a correlation, not a controlled experiment ([Devin 2.1](https://cognition.com/blog/devin-2-1)). Series D, 2026-05-27: **89% of code committed by their engineers is committed by Devin**, and the rest by local agents in Windsurf. That is a share of commits, not a share of proposals that survived review. Also **>10×** enterprise usage since the start of the year and **$492M** run-rate revenue. Mercedes-Benz cutting an eight-month modernization to eight days is a customer story in a fundraise post, not a methods section ([More Devins in More Places](https://cognition.ai/blog/series-d)).

Devin Fusion, 2026-06-29, search extract of their benchmark table, data last updated 2026-08-07. FrontierCode 1.1 Extended, score then cost: **Fable 5 (xhigh) 64.9 at $10.53; Opus 5 (medium) 63.6 at $3.51; Devin Fusion 63.1 at $1.35; GPT-5.6 Sol (high) 58.7 at $3.41**. They call this frontier performance at **60% lower cost**, and the post says **up to 60%**. The $1.35 versus $10.53 ratio is about **87% lower**, which the notes do not collapse into the 60% line. This is their benchmark, not a production pull-request ledger ([Devin Fusion](https://cognition.com/blog/devin-fusion)).

### OpenAI, lab

Ryan Lopopolo, essay dated 2026-02-11. This pass read the Traditional Chinese mirror, not the English URL. Wording here is a reading of that mirror. An internal beta. First commit in late August 2025 on an empty repository. No handwritten code. Humans steer by prompt. Codex opens the pull request. To finish one they tell Codex to review itself locally, ask other agents to review locally and in the cloud, and iterate **until all agent reviewers are satisfied**. The essay calls that a Ralph Wiggum loop. Humans may review and do not have to. Over time almost all review went to agents. One app instance and a short-lived observability stack per git worktree. `AGENTS.md` is a map of **about 100 lines** into `docs/`, not an encyclopedia. Custom linters and structural tests enforce layering, and the linter carries the fix instruction in the error. A doc-gardening agent opens fix pull requests ([Harness engineering, zh-Hant](https://openai.com/zh-Hant-HK/index/harness-engineering/)).

After five months, against their own repo: **about 1,000,000 lines, about 1,500 pull requests opened and merged, by 3 engineers, on average 3.5 pull requests per engineer per day**. The team later grew to 7 and throughput went up. No new rate is given. They estimate Codex did it in **about one tenth** the time of writing the code by hand. The tenth is an estimate, not a paired stopwatch study. Hundreds of internal users, some daily. Single Codex runs **often over 6 hours**, usually while the engineer is asleep. They used to spend Friday, **20% of the week**, cleaning AI slop. That did not scale. They replaced it with scheduled Codex refactor pull requests, most reviewable within a minute and auto-merged. Merge gates are mostly non-blocking. Flaky tests are rerun rather than held. A single large `AGENTS.md` had already failed: context is scarce, when everything is important nothing is, the file rots, and it is hard to lint ([zh-Hant mirror](https://openai.com/zh-Hant-HK/index/harness-engineering/)).

The English page was not fetched. ZenML's retelling, which adds about 1 billion tokens a day and 5–10 pull requests per engineer per day, contradicts the essay text read here and is rejected in the recap list below.

## What they tried and killed

The failures they describe in their own systems are the same list. A giant always-on instruction file that cannot be checked. Parallel writers that cannot see each other's choices. A long unattended coordinator that is allowed to invent the next task. Role-play in the prompt. An LLM judge with no executable oracle, used as the merge decision for code that is supposed to last.

OpenAI's large `AGENTS.md` failed in a predictable way and was replaced by the ~100-line map plus versioned docs and a doc-gardening agent ([zh-Hant mirror](https://openai.com/zh-Hant-HK/index/harness-engineering/)). Steinberger kept the opposite artifact on purpose, the ~800-line scar log, and he already deletes notes the model has absorbed. Instruction-file size is not the variable. The failure OpenAI names is a file that crowds out the task. The file Steinberger kept is a log of concrete misses ([just talk to it](https://steipete.me/posts/just-talk-to-it)). Hashimoto's version of the same idea is one line, or one tool, per observed mistake ([Hashimoto](https://mitchellh.com/writing/my-ai-adoption-journey)).

Role-play prompts were rejected by Steinberger and, from the other side, by Yan in June 2025 ([just talk to it](https://steipete.me/posts/just-talk-to-it), [Don't Build Multi-Agents](https://cognition.com/blog/dont-build-multi-agents)). Zechner refused to put MCP, plan mode, to-dos, subagents, permission prompts, and a 10,000-token system prompt into pi. The tool list is a tax on every turn. A subagent is a black box inside a black box, and context transfer is poor. He kept bash, including the option to have pi run itself, and tmux instead of a background-bash feature ([pi](https://www.mariozechner.at/posts/2025-11-30-pi-coding-agent/)).

Ronacher's factory is the killed run with a log: 35 hours, about $1,200, 79 commits, nothing he would keep ([Astra](https://lucumr.pocoo.org/2026/9/7/astra-why/)). Yegge's first two orchestrators failed; the Python one lasted six or eight weeks; the Go one then did 17 days and 2,000 commits; by 2026-11-14 he is telling audiences that factories are mostly upkeep ([Gas Town](https://steve-yegge.medium.com/welcome-to-gas-town-4f25ee16dd04), [quoted notes](https://x.com/AGTPinsights/status/2121732981975101767)). Steinberger dropped worktrees, per-change branches, and a list of named harnesses. He runs one dev server and clicks through changes. Isolated large commits become impossible, so he throws many small bombs or one large one, not several large ones ([just talk to it](https://steipete.me/posts/just-talk-to-it)).

Cognition is the outlier that walked "don't build multi-agents" back only for read-only helpers, a clean-context review, and a manager. They still call free-form swarms a distraction. The 2026-04-22 post says the original observation still holds for parallel writers, and it names the manager failures: overly prescriptive, assumed shared state, no cross-agent communication by default ([Multi-Agents](https://cognition.com/blog/multi-agents-working)). "Subagents failed" is too coarse. The failure they keep reporting is a second writer with a partial copy of the task. A second process that only reads, or that only looks at the diff in a fresh context, is the version Zechner and Cognition still use.

Always-on coordinators fail in the stories where the coordinator invents the next task: the Astra factory, Yegge's game outrunning its players, OpenAI's Friday slop hour. They are tolerated where a human or a test still picks the next unit: Ralph's one item, MiniJinja's failing snapshot, Hashimoto's one background agent. Nobody in this set published a controlled comparison of swarm versus one agent on the same tasks with the same acceptance bar. Cognition's Fusion table is model routing on a benchmark. Hotz's 10× is a shrug. Steinberger's 5–10× is a price difference between subscription and API.

Nobody published a diff-only re-review that is cheaper by a measured token factor. Cognition's argument is attention, not a bill, and they say the loop can take a while ([Multi-Agents](https://cognition.com/blog/multi-agents-working)). Steinberger mostly does not re-review with a model at all. No individual builder published a review-round cap with a count of grader passes. OpenAI's loop is explicitly unbounded. Huntley's chapter title "why LLM-as-judge isn't enough" is on a page this pass opened only as an outline, so the title is not a finding ([agency](https://ghuntley.com/agency/)).

## Mechanisms that exist as code

Checked 2026-11-23 against the GitHub API, default-branch HEAD, and raw files. A commit-landing loop that is actually small is one agent, a handful of tools, and either the agent commits or the user commits. Outer loops that survived are a bash iteration cap, a tracker poll with a per-issue workspace, or a worktree plus a capacity count. The judge of "is the code right" is still the agent's tests or a human, except where a script gate is explicit. No surveyed repo showed a commit that removed a multi-agent layer because it cost too much. Expense shows up as open bugs and unfixed proposals.

## Distillation

Two loop shapes have a measured result tied to a named run the author then kept or killed. Several shapes have a manifesto, a launch-week size, or a lab throughput number that does not say what share of the diffs was thrown away.

The kept run with a full log is MiniJinja. One pi session. An oracle that already existed, the Rust snapshot suite, which the model did not grade. A human who spent about 45 minutes, in 34 prompts, refusing two semantic regressions, then went to sleep for the rest of a 10-hour, $60, 2.2-million-token run ([MiniJinja port](https://lucumr.pocoo.org/2026/1/14/minijinja-go-port/)). The killed run with a full log is Astra. The model managed its own context, spawned subagents, and invented the next task. Thirty-five hours, about $1,200, about 1 billion tokens on the run log, 79 commits, 75k lines, and nothing he would keep. The 4 billion figure in the same post is a different estimate and is not the run log ([Astra](https://lucumr.pocoo.org/2026/9/7/astra-why/)). Ronacher's general claim matches those two logs. The outer loop is what he trusts for a port or a measurement. It is what he does not trust for code he means to keep, because each unattended iteration adds a defense and the system gets harder to explain ([The Coming Loop](https://lucumr.pocoo.org/2026/6/23/the-coming-loop/)).

The lab runs are measured and they are a different bet. OpenAI, read here only in the zh-Hant mirror, kept a million-line repository: about 1,500 merged pull requests, three engineers at 3.5 a day, runs that often exceed six hours, and a Friday that used to be 20% of the week spent deleting slop. They estimate a tenth of the time of writing by hand. They also removed the requirement that a human review, and they replaced the cleanup day with more agent cleanup. The "until every agent reviewer is satisfied" loop is unbounded on purpose. It is a choice to spend agent time instead of human time. It is not a recipe for cheap grader tokens. The architectural grader they trust is a linter whose error text contains the fix, not a model saying the layering looks right ([zh-Hant mirror](https://openai.com/zh-Hant-HK/index/harness-engineering/)). Cognition, also a lab, measured a clean-context reviewer at about 2 bugs per pull request, 58% of them severe, and measured 89% of engineer commits as Devin's. The 89% is a commit share. It is not a keep-rate of proposals. They still say parallel writers have no meaningful adoption, and they published no token cost for the review loop they say can take a while. The Fusion table is a benchmark cost, and the "up to 60%" line does not match the $1.35 versus $10.53 row ([Multi-Agents](https://cognition.com/blog/multi-agents-working), [series D](https://cognition.ai/blog/series-d), [Fusion](https://cognition.com/blog/devin-fusion)).

The other builders published a shape and a refusal, and a number that is not a keep-rate. Zechner's harness is under 1,000 tokens and four tools, used in seven unnamed production projects, with a leaderboard he published as an image this pass could not read. Steinberger names a 300k-line product and a subscription bill around $1k a month, with a 5–10× band he told the reader not to nail down, and he is the coordinator of 3–8 visible sessions. Yegge's 17 days, 75k lines, and 2,000 commits are a launch-week size from a search extract, with no acceptance rate, and the later quote is to slow down. Hotz's 10× and 100× are questions.

What shows up in the runs that finished something the author would keep is not "a harness" and not "no harness." It is one writer, and a check the model cannot satisfy by editing the story of what it did. The writer is one session (MiniJinja, pi, Hashimoto's single background agent) or several top-level sessions a person can see and stop (Steinberger). It is not a child that writes while the parent also writes, which Zechner, Yan, and the Astra post each describe as the failure. The check is a snapshot suite, a compiler, a linter, or a human who hits escape when the blast radius is wrong. Where a second model is still in the kept path, it reads. Cognition's reviewer looks at the diff from a clean window and re-discovers context. Zechner opens a new pi to review. Neither of them published a token saving for that, and Steinberger mostly skipped it because a fresh context spent ten minutes rereading. Fresh context is how they avoid making the writer reread its own trail. It is also a cost. Both of those sentences are in the posts. They do not cancel.

The manifesto shapes are the ones with roles, tenets, or a README score and no run log. Loom has tenets and no measured job. Gas Town has roles in Go, an open issue asking for a cost rollup, and a launch post with no merge rate. CCPM's percentages are a README. OpenSpec is a prompt the host assistant runs. HumanLayer's open-source post has an architecture and no review-round count. Symphony has the most serious code of the orchestrators, and what it implemented is one Codex child per issue, a turn cap of 20, token counters, and a human-review state. It did not implement a grader model as the thing that allows the commit. Ralph's public runner will declare victory on a string the model prints. The prompt tells the agent to run the tests first. The shell cannot tell whether it did.

The pattern, stated so it can be compared with backpack: the author stays one context a person can still steer; the next unit of work is picked by a test or by that person, not by the agent; a fresh context is for a review or for the next task, not for a second writer; an unattended loop without an oracle is the thing the measured kill (Astra) and the later Yegge quote both refuse. The lab that deleted the human published throughput and a cleanup loop, not a fraction of agent diffs kept. No source opened here gives grader-token cost per feature.

## Proposed optimizations

These are proposals. They are not a decision to build, and they are not a ranking of what the owner should want. Rank is by what the written numbers imply for wall time first and for tokens second. Where the notes do not price a change, the entry says so. Nothing below adds a role, a manager, a town, or a review-until-satisfied loop. Those are the shapes the measured kill and the unpriced lab spend already cover.

### 1. Stop paying a model grade on every cycle when a person is already in the session

**Change.** Use the ordinary session, or [plans/direct.yaml](/Users/whycz/m/bp3/plans/direct.yaml) (`max_cycles: 0`, `grade.required: false`), for work the owner is watching. Do not spawn the cold grader.

**Evidence.** This is the largest cut the files allow. It removes the fresh grader, the grade desk, the second context, and the re-judge. On the only multi-hour node, **9.4 of 14.3 hours** sat in `handed_off` ([fast-grader QUEST](/Users/whycz/m/bp3/docs/quests/2026-11-19-fast-grader/QUEST.md)). On the one grade whose spend was counted, the processed total was about **5.75 million tokens, almost all cache reads** ([metric-collectors QUEST](/Users/whycz/m/bp3/docs/quests/2026-11-21-metric-collectors/QUEST.md)). Steinberger hits escape and does not pay a second model per commit ([just talk to it](https://steipete.me/posts/just-talk-to-it)). Hashimoto does not add a model grader ([Hashimoto](https://mitchellh.com/writing/my-ai-adoption-journey)). Ronacher's kept port used the snapshot suite, not a model, as the oracle ([MiniJinja port](https://lucumr.pocoo.org/2026/1/14/minijinja-go-port/)).

**What it breaks.** The independent verdict bound to the commit. The inline author is specified never to form the verdict. About half of the test-pyramid findings were tests that could not fail or claims beyond the evidence, which is the class a same-session author is the worst judge of. Lobsters commenters say the same thing as hearsay: a session that writes the code and the tests writes weak tests ([kornel](https://lobste.rs/s/miwcai/do_you_let_llms_write_both_your_tests_your)). The files contain no timed comparison of a single prompted session against induct-inline. The sentence "sometimes the old way is faster" is the question, not a result.

**Already iceboxed.** Not this. The direct plan exists and was not checked for use. The frozen yolo-decider would auto-resume at the cap, which is the opposite move ([yolo-decider icebox](/Users/whycz/m/bp3/docs/icebox/2026-11-19-yolo-decider.md)). The landed yolo skills still grade.

**Wrong if.** The owner will not look, which is why the cap went to 10. Also wrong if the bugs that matter are the ones only a fresh reader finds. Cognition's 2 bugs per pull request is the lab's argument for keeping a clean-context reader, and they did not price it ([Multi-Agents](https://cognition.com/blog/multi-agents-working)).

### 2. Cap repeat full re-grades, and do not let the grader be the one who edits

**Change.** Thaw only the fast-grader limits that cut rounds: on the order of one re-grade per node, and the wall caps already written there (about five minutes for a grade, about fifteen for a re-grade). Leave frozen the clause where the grader writes the fix. The author session already applies `needs_fix`. That is one writer. A grader who edits is a second writer, which is the failure mode in the builder posts.

**Evidence.** Sixteen of twenty-five test-pyramid grades were re-grades. tier.1's written wall is dominated by `handed_off` dwell. The icebox says a delta brief cut later rounds to **7–15 minutes**, from a band it writes as 7–35 ([fast-grader icebox](/Users/whycz/m/bp3/docs/icebox/2026-11-19-fast-grader.md)). The cap of 10 multiplies the worst case and was not what any measured quest ran to the end ([plans/default.yaml](/Users/whycz/m/bp3/plans/default.yaml)). Ronacher's rule after Astra is not to leave this class of model on one prompt ([Astra](https://lucumr.pocoo.org/2026/9/7/astra-why/)). No builder published a round cap of their own. OpenAI's is unbounded, and that is the expensive lab choice.

**What it breaks.** A real defect that needs several rounds. The constraints lesson, as copied into the backpack note from CONTEXT.md, says one runner took six grading rounds before an OCaml rewrite. Not re-checked against a primary source beyond that citation. A five-minute cap can also cut off `GRADING.md`'s plant-a-bug step. The 201-second median is already under five minutes. The 11-minute median and the 1,280-second grade are not. A cap changes the tail and the repeats. It does not change a grade that is already short.

**Already iceboxed.** The whole fast-grader quest is `proposed`, and the icebox is `frozen`. The 2026-11-22 quest took none of its decisions and left a time cap and delta-only grading out of scope ([2026-11-22 QUEST](/Users/whycz/m/bp3/docs/quests/2026-11-22-induct-inline-as-default-measure-author/QUEST.md)). The frozen yolo-mode sketch would raise `max_cycles` further, which moves wall time the other way ([yolo-mode icebox](/Users/whycz/m/bp3/docs/icebox/2026-11-18-yolo-mode.md)). The landed yolo budget is in grades or wall minutes and the notes do not say whether it stops a grade already in progress. It is not a substitute for a shorter grade. Yolo does not skip grades.

**Wrong if.** The rounds are converging on code the owner would keep, and the alternative is a page, which the owner asked to remove. Also wrong if "one re-grade" is applied to a constraints-class finding. The inline skill already stops on those and pitches `/teach` instead of fixing.

### 3. On cycle two and later, grade the diff, and do not paste the previous verdict

**Change.** Do what the icebox sketch already says for round two and after: prior findings, the diff, and `make check-full`, with the fifteen-minute cap. Do not also paste `--reason` as the verdict to confirm. The 2026-11-22 brief already shows the diff and then orders a full re-judge, and it withholds `--reason` on purpose.

**Evidence.** The icebox's own sentence is that a delta brief cut later rounds to 7–15 minutes. ### 4. Turn repeated model findings into a check the author cannot quietly rewrite

**Change.** When a grade keeps finding the same class of bug, encode it as a test or a lint, the way Hashimoto writes one line or one tool per mistake and the way OpenAI puts the fix text in the linter error. The first target the census already names is a test that cannot fail. Do not add a model as the linter.

**Evidence.** About half the test-pyramid findings were tests that could not fail or claims beyond the evidence ([fast-grader QUEST](/Users/whycz/m/bp3/docs/quests/2026-11-19-fast-grader/QUEST.md)). Huntley's stop condition is a deterministic check, which he separates from skills ([answer](https://ghuntley.com/answer/)). MiniJinja's oracle was the snapshot suite, and the failure mode was the agent giving up on must-fail tests and trying to regress behavior the human cared about ([MiniJinja port](https://lucumr.pocoo.org/2026/1/14/minijinja-go-port/)). Tinygrad's in-repo gate is an assert on line count, not a model ([sz.py](https://github.com/tinygrad/tinygrad/blob/fbb253b67f9ddac0f24a8453606c3f7942ce36bf/sz.py)). thefunnyman's HN comment says the same thing and is hearsay ([50540834](https://news.ycombinator.com/item?id=50540834)). On the 2026-11-22 split, tool time is 5–53 seconds of a grade whose rest is model turns. This proposal does not remove the 11-minute grade. It removes the reason to spend a later grade on a bug a program can now see.

**What it breaks.** Judgment calls and one-off design findings, which a lint cannot hold. A check the author can edit is not an oracle. MiniJinja is the case. The grader is already forbidden to edit. The author is not.

**Already iceboxed.** Not as its own entry. The fast-grader sketch does say the author plants the regression before handoff. What landed instead is the plant-a-bug rule on the grader's side of `GRADING.md`, which spends grader time to prove the check can go red. Grade-model routing is a different icebox and does not belong in this proposal.

**Wrong if.** The findings do not repeat, so there is nothing stable to encode. The census did not sort findings into stable and one-off. Also wrong if the check is treated as a replacement for the human on code that is supposed to last. Ronacher's position is that an LLM signal can continue a loop and is not, by itself, a merge decision for that code. OpenAI's position, the lab one, is that they built the linters and still ran agents for hours.

### 5. If full induct is what a session actually runs, stop paying an agent to read state and to type the cast

**Change.** On the non-default path, the conductor runs `bp3 q` for the state read and for the cast. Keep the grader as the only extra model, and keep the grader from calling `bp3 q`, which is why the cast was split off.

**Evidence.** [induct-node.js](/Users/whycz/m/bp3/skills/induct/workflows/induct-node.js) spends a `host.agent` on `readState` and another on the apply step, every transition, up to 12 edge dispatches. **What it breaks.** The conductor rule that the main session does not do a step's work, and the pure-grade split in `4ab3228`. **Already iceboxed.** The fast-grader quest left "retire or align the 1,022-line `induct-grade.js`" as an open question for the owner. The line count is unchanged. The 2026-11-22 quest did not delete induct or the workflow steps.

**Wrong if.** The isolation is the point: the conductor's context must not be the context that reads state or casts, because that context is long and the children are supposed to be cold. The notes infer that. They do not measure the token cost of the conductor's 291-line skill.
