# Run notes — exp-dogfood-1-link-drive (handoff, cycle 1)

## What was built

- [test/dogfood-link.sh](../../../../../../../test/dogfood-link.sh):
  the drive is the test. Four flappy drives (old/link ×
  muse/pi session shapes) in a temp repo; each artifact's

  and the shellcheck lint list.
- This run folder holds the observed drive: four
  `flappy-*.html` artifacts, `old-brief.txt`,
  `link-brief-*.txt`, `metrics.json`, `attacks.log` —
  all generated by a real mint/claim drive against
  this repo's `bp3`, not estimated.

## Observed (this run)

- brief chars: old 425 vs link-muse 70, link-pi 68.
  The link brief is one line (`claim <token>, build
  flappy …`) with no export/desk/run-id prose; the
  fixture asserts that shape and that no link-way
  call after claim carries graph/node/run-id args.
- attacks refused before work (see `attacks.log`):
  duplicate claim `E_LINK_SPENT` naming the first
  claimant; quoting claim `E_NOT_FOUND` (a token in
  a brief confers nothing); wrong-desk `bp3 e`
  `E_NO_CONTEXT`. Zero setup cycles burned.
- Pi nested tree and supervisor fold are asserted
  in the fixture: distinct root/node/edge claims
  reconstruct via `parent_run_id`/depth, and the
  supervisor derives `finished` from the run config.

## Lessons

- No product code changed: mvp.1/mvp.2 already carry
  the link behavior; this exp's missing piece was
  the measured A/B proof, so the fixture is the
  deliverable.
- Wrong-desk refusal lives at context resolution,
  not at claim: claiming from another cwd is a
  settled mvp.2 pattern (the desk is where context
  is written), so the attack is proven at the
  `bp3 e` rung. A claim-time desk refusal was tried
  and reverted — it broke `test/context.sh`.
- Pi rows use the dispatcher's session-file shape
  (`PI_SESSION_FILE`), as in `test/link.sh`; a live
  Pi session drive remains for the Pi arm's owner.
  Metrics mark nothing zero that was not measured:
  second-granularity timing is reported as observed.
