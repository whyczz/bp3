## Who is shipping real software with a harness, and what is the harness shape?

### Takeaway
The people actually shipping code split into four shapes, and the 2026 updates did not collapse them into one: a fresh-context bash loop with one task and a deterministic check (Huntley); one minimal coding agent in one session, human in the loop, no built-in subagents (Zechner, and Ronacher when he cares about the code); several independent sessions in one working tree, human as the only coordinator (Steinberger, Hashimoto with a single background agent); and a lab or product harness where a coordinator, a clean-context reviewer, or a tracker drives workers (OpenAI's Codex repo, Cognition's Devin, Yegge's Gas Town). Loops that decide "done" without the human are what Ronacher says works for ports and measurement, and what he says he does not trust for code he means to keep.

### Cited Findings
- Geoffrey Huntley, Ralph, post dated 2025-07-14. Ralph "in its purest form" is `while :; do cat PROMPT.md | claude-code ; done`. "Ralph works autonomously in a single repository as a single process that performs one task per loop." He calls the technique "deterministically bad in an undeterministic world." No coordinator, no role-played workers. — [Ralph](https://ghuntley.com/ralph/)
- Huntley, 2026-11-11, "the answer to ai is engineering." "The best way to stop it closing on bad output is deterministic checks. These aren't skills. This is engineering again." His loops run as root inside a throwaway Nix machine so the agent can inspect the database and journals; he says he would not do that on Ubuntu. He says his loop style "is very different from Steve's." — [the answer to ai is engineering](https://ghuntley.com/answer/)
- Huntley, 2026-03-15, porting recipe: one Ralph loop writes specs from tests, another writes specs from `src/` with citations back to the source, then "a classic ralph — doing just one thing and the most important thing per loop," with a strict compiler on the target language. — [porting](https://ghuntley.com/porting/)
- Huntley, X, 2025-12-29. He said Ralph "exists as a first class harness now" called Loom, then unreleased, with tenets: self-hosted, "alloying the best models," "tight scm integration," "no human steering," remote async jobs, IDE only as a "crash cart." No ship date or usage count in that post. — [Loom tweet](https://x.com/GeoffreyHuntley/status/2005548106797207766)
- Mario Zechner, pi, 2025-11-30. He ships pi, the coding agent, because Claude Code "has turned into a spaceship with 80% of functionality I have no use for" and its prompt and tools "change on every release." Shape he kept: system prompt plus four tools (`read`, `write`, `edit`, `bash`) "below 1000 tokens"; "YOLO by default"; no to-do tool, no plan mode, no MCP, no background bash, no sub-agent tool. Plans, if any, are a markdown file on disk. AGENTS.md is the only injected context. He says pi-ai "has been used in seven different production projects" (projects not named in the post). — [pi](https://www.mariozechner.at/posts/2025-11-30-pi-coding-agent/)
- Zechner, year in review, 2025-12-22. Same refusals restated: "No MCP support, no built-in sub-agents, no plan mode, no to-do tool." He points at Peter Steinberger's Clawdis as an agent built on pi, not as pi's own orchestration. — [year in review 2025](https://mariozechner.at/posts/2025-12-22-year-in-review-2025/)
- Zechner, Agents Anonymous Vienna slides, page dated 2026-01-27 in the URL. Slides repeat: minimal system prompt "(<1000 tokens)", "4 tools: read, write, edit, bash", "YOLO by default", and a slide titled "what's NOT built in." — [slides](https://mariozechner.at/uploads/2026-01-27-agents-anonymous-vienna/)
- Zechner on subagents, same 2025-11-30 post. Claude Code plan mode "usually spawns a sub-agent and you have zero visibility." His rule: if you need context, gather it "first in its own session" and "create an artifact" for a fresh session. "Spawning multiple sub-agents to implement various features in parallel is an anti-pattern in my book and doesn't work, unless you don't care if your codebase devolves into a pile of garbage." He does spawn pi via bash for a code review, then says that in practice he "would just spawn a new pi session" and review with it. — [pi](https://www.mariozechner.at/posts/2025-11-30-pi-coding-agent/)
- Armin Ronacher, 2026-06-23, "The Coming Loop." Two loops: the in-agent tool loop, and a harness loop outside it that "decides whether that was actually the end" by continuing the session, starting a fresh one, or sending the task elsewhere. He credits Ralph as prior art. He says he has "not had much success with this way of working for code I deeply care about." He says Pi "has been cautious" and he does not want it to become "an uncontrolled swarm." — [The Coming Loop](https://lucumr.pocoo.org/2026/6/23/the-coming-loop/)
- Ronacher, MiniJinja to Go, 2026-01-14. Shape that shipped a real port: one pi session, voice prompts, Opus 4.5 then GPT-5.2 Codex, snapshot tests as the oracle, pi branch-switch instead of a new coordinator. PR [#854](https://github.com/mitsuhiko/minijinja/pull/854). — [MiniJinja port](https://lucumr.pocoo.org/2026/1/14/minijinja-go-port/)
- Ronacher, 2026-05-24, "Building Pi With Pi" (search extract, not a full read). They use Pi to build Pi. Parallelism "is mostly for reproducing issues." A committed prompt `/is` "explicitly tells the agent not to trust the analysis in the issue and to derive its own diagnosis from the code." — [Building Pi With Pi](https://lucumr.pocoo.org/2026/5/24/pi-oss/)
- Ronacher, 2026-10-06, Codemode. Pi 1.0 added MCP by letting the model write code that runs in QuickJS inside WASM in the harness, "no network, no file system, no timers, limited RAM," and the only effect is to call more tools. This is a context-firewall for tools, not a worker swarm. — [What is Codemode](https://lucumr.pocoo.org/2026/10/6/codemode/)
- Peter Steinberger, "Just talk to it" (publication date not in the extracted HTML; the post links X posts from October 2025; fetched 2026-11-23). He says agentic engineering "writes pretty much 100% of my code." Shape: Codex CLI, "between 3-8 in parallel" in a 3x3 grid, "most of them in the same folder." He "experimented with worktrees, PRs but always revert[s] back." Agents make their own atomic commits. He is the coordinator; he tells subagents to get lost and uses another window instead. Product he names: "~300k LOC TypeScript React app, a Chrome extension, a cli, a client app in Tauri and a mobile app in Expo," hosted on Vercel. — [just talk to it](https://steipete.me/posts/just-talk-to-it)
- Mitchell Hashimoto, 2026-02-05, hand-written. Ghostty / Zed-era workflow, not a productized harness. Steps he actually uses: agent with read, exec, and HTTP; tasks split across sessions; planning session separate from execution; a verifier; one background agent, not many. "I'm not [yet?] running multiple agents, and currently don't really want to." Background-agent goal is met "maybe ... 10 to 20% of a normal working day." Amp "deep mode" (he says "basically just GPT-5.2-Codex") "can take upwards of 30+ minutes." — [My AI Adoption Journey](https://mitchellh.com/writing/my-ai-adoption-journey)
- OpenAI, Ryan Lopopolo, essay dated 2026-02-11, read 2026-11-23 on the zh-Hant mirror. Lab. An internal beta, first commit "2025 年 8 月下旬" on an empty repo, "完全沒有手寫程式碼." Humans steer by prompt; Codex opens the PR. To finish a PR they tell Codex to review itself locally, ask other agents to review locally and in the cloud, and iterate "until all agent reviewers are satisfied," which the essay itself calls a Ralph Wiggum loop. Humans "may review a pull request, but do not have to"; over time "almost all review" went to agents. One app instance and a short-lived observability stack per git worktree. `AGENTS.md` is a map of about 100 lines into `docs/`, not an encyclopedia. Custom linters and structural tests enforce layering. A doc-gardening agent opens fix PRs. — [Harness engineering (zh-Hant)](https://openai.com/zh-Hant-HK/index/harness-engineering/)
- Cognition, Walden Yan, "Don't Build Multi-Agents," blog index date 2025-06-12; the 2026-04-22 follow-up says "10 months ago." Default shape: one linear agent. Subagents only to answer a question, not to write code in parallel, and the parent does not work in parallel with them. A second model may compress history; they say they have fine-tuned a smaller model for that. Parallel writers are "fragile" because "actions carry implicit decisions." — [Don't Build Multi-Agents](https://cognition.com/blog/dont-build-multi-agents); index line on [cognition.ai/blog/2](https://cognition.ai/blog/2)
- Cognition, Walden Yan, 2026-04-22. Update, still first party: "parallel-writer swarms" still "don't see meaningful adoption." What they say works is "multiple agents contribute intelligence to a task while writes stay single-threaded." Concrete shapes: Devin Review in a clean context, looped with the author; a "smart friend" tool the primary model calls; a manager Devin that splits work to child Devins over an internal MCP. "The unstructured-swarm approach ... is mostly a distraction." Read-only subagents "mostly resemble tool calls." — [Multi-Agents: What's Actually Working](https://cognition.com/blog/multi-agents-working)

Coordinator Devin assigns scoped pieces to managed Devins, each in its own VM with its own shell and test runner. ### Inferences
- "One agent" in this set means two different things. Zechner and Hashimoto mean one writer in one context. Steinberger means many writers, but each is a top-level session he can see, not a child the parent spawned. Cognition's 2026 position is the third: many models may think, only one may write.
- Fresh context is doing the work that role-played subagents were supposed to do. Huntley's loop, Zechner's "artifact then a new session," Cognition's clean-context reviewer, and OpenAI's short `AGENTS.md` plus `docs/` are the same move: do not make the writer reread its own trail.
- The lab shape (OpenAI, Cognition manager Devins) is the one that removed the human from the merge. The individual builders who still like the code (Ronacher, Zechner, Hashimoto) did not.

## What did they try that failed, and what did they keep?

### Takeaway
The failures they describe in their own systems are the same list: a giant always-on instruction file, parallel writers that cannot see each other's choices, a long unattended coordinator, role-play in the prompt, and an LLM judge with no executable oracle. What they kept is a small always-loaded map, one writer, checks the model cannot talk its way past, and a human who can still explain the system. Cognition is the outlier that walked back "don't build multi-agents" only for read-only helpers, clean-context review, and a manager, and they still call free-form swarms a distraction.

### Cited Findings
- Giant instruction file, failed, then replaced. OpenAI: a single large `AGENTS.md` "failed in a predictable way." Context is scarce, "when everything is important nothing is," the file "rots immediately," and it is hard to lint. They kept a ~100-line map plus versioned `docs/`, plans, and a doc-gardening agent. — [OpenAI](https://openai.com/zh-Hant-HK/index/harness-engineering/)
- Steinberger kept the opposite artifact on purpose. Agents.md is "~800 lines" and "a collection of organizational scar tissue." "I didn't write it, codex did, and anytime something happens I ask it to make a concise note." He says GPT-5 honors it more often than Claude did, and that he "should clean this up." He also says he deleted Tailwind 4 guidance once the models already knew it. So the file is a log of misses, and he expects it to shrink when the model catches up. Not a claim that 800 lines is optimal. — [just talk to it](https://steipete.me/posts/just-talk-to-it)
- Hashimoto, the rule he kept, 2026-02-05. "Anytime you find an agent makes a mistake, you take the time to engineer a solution such that the agent never makes that mistake again," either a line in AGENTS.md or a real tool. He links a Ghostty `src/inspector/AGENTS.md` where "each line ... is based on a bad agent behavior." — [Hashimoto](https://mitchellh.com/writing/my-ai-adoption-journey)
- Role-play prompts, rejected by the people who tried them. Steinberger, on an "AI Engineer" subagent prompt: "telling your model 'You are an AI engineer specializing in production-grade LLM applications' will not change that." He calls the file "an amalgamation of slop" and "context poison." "Don't waste your time on stuff like RAG, subagents, Agents 2.0 or other things that are mostly just charade." — [just talk to it](https://steipete.me/posts/just-talk-to-it)
- Cognition, 2025-06-12, same rejection from the other side. "You're a senior software engineer" and "think for longer" are "gimmicky." Context engineering is the job. Parallel subagents that split a task and merge it are the architecture he says to rule out by default. Claude Code's then-current subagents are cited as the acceptable version: they answer a question, they do not write code in parallel. — [Don't Build Multi-Agents](https://cognition.com/blog/dont-build-multi-agents)
- Cognition, 2026-04-22, what the follow-up says still failed. "Our original observations still hold today for parallel-writer swarms." "Smart friend" with SWE-1.5 as the primary "was not good enough": "the gap between it and Sonnet 4.5 was too wide" at "knowing when to escalate, knowing what to ask." "The cost and speed wins were real, but the quality ceiling was set by the primary." Cross-frontier smart-friend (Claude and GPT) "produced real gains in the trickiest scenarios." Manager Devins: "getting it to feel coherent took more context engineering than we expected." Failures they name: managers "default to being overly prescriptive," agents "assume they share state with their children when they don't," and "cross-agent communication ... doesn't happen by default." — [Multi-Agents](https://cognition.com/blog/multi-agents-working)
- Zechner, what he refused to build into pi, 2025-11-30 and 2025-12-22. MCP in the core, plan mode, to-dos, subagents, permission prompts, a 10,000-token system prompt. Reason for MCP: the tool list is a tax on every turn. Reason for subagents: "a black box within a black box" and "context transfer between agents is also poor." He kept bash, including "ask pi to run itself" if you insist, and tmux instead of a background-bash feature. — [pi](https://www.mariozechner.at/posts/2025-11-30-pi-coding-agent/)
- Ronacher, the factory he ran and killed, 2026-09-07. Setup: model "free to manage its own context," notes in `agent-notes/`, "spun off subagents." Result: task ids decaying into "8b2c2b3," code-golfed Python used as the edit tool, constants and one-line macros he says do not match the codebase, 35 hours, nothing he would keep. "I honestly do not need an agent to run for 35 hours on a single prompt. It clearly does not work." He says the same failure mode shows up in ordinary Astra sessions, not only in the factory, and that subagents are where "the agent believes nobody is looking." — [Astra](https://lucumr.pocoo.org/2026/9/7/astra-why/)
- Ronacher, 2026-06-23, the loop failure mode when the code is meant to last. Models "produce code that is too defensive, too complex, too local." "If each iteration adds another small defense, the system slowly becomes less understandable while appearing more robust. The more hands-off you are, the more that happens." He says Claude Code with Fable "working uninterrupted ... for thirty minutes or more" produces worse code, by his taste, than the more human-in-the-loop process of the previous autumn. Not a scored eval. What he says the loop is good at: porting, performance search, security scanning, research, and "artifacts without necessity of longevity." — [The Coming Loop](https://lucumr.pocoo.org/2026/6/23/the-coming-loop/)
- Ronacher, MiniJinja, the pushes he had to undo, 2026-01-14. The agent "completely gave up on all the must-fail tests" because error strings would not match, and it "wanted to regress behavior" he cared about (HTML escaping, `range` returning an iterator). He kept the run only after steering those. The design change he let stand, because it fit Go: a tree-walking interpreter and reflection, instead of his Rust bytecode interpreter. — [MiniJinja port](https://lucumr.pocoo.org/2026/1/14/minijinja-go-port/)
- Yegge, launch extract. Two orchestrators "failed" before Beads and the Python Gas Town that lasted "six or eight weeks." The Go Gas Town then did 17 days and 2,000 commits. By 2026-11-14 he is telling conference audiences that factories are mostly upkeep and that his own game's agents outran the humans. — [Gas Town](https://steve-yegge.medium.com/welcome-to-gas-town-4f25ee16dd04), [quoted talk notes](https://x.com/AGTPinsights/status/2121732981975101767)
- HumanLayer, Kyle, 2026-03-23, their own trial. "We tried Opus with 1M context for coding agents, and now we're switching back." Longer context made them use subagents "even more aggressively," and he published a `subagent-orchestrator` skill that delegates research and noisy bash. No before/after score. This is their experiment, not a restatement of a lab post. — [Long-Context Isn't the Answer](https://humanlayer.dev/blog/long-context-isnt-the-answer)
- Steinberger on harnesses he tried and dropped. Worktrees and per-change branches: slower, because he runs one dev server and clicks through several changes. Conductor, Terragon, Sculptor, and "1000 other ones": "none stick." Web agents: Devin, Cursor, and Codex tried; "the only one that stuck is codex web," and only as a phone-side scratch pad he reviews later on the Mac. Jules "really annoying to set up." Amp: he uses Codex instead, because Amp demoted GPT-5 to an "oracle" while he wants that model as the worker. — [just talk to it](https://steipete.me/posts/just-talk-to-it)
- LLM-as-judge, kept only with a narrow reading. Ronacher, 2026-06-23: "Many successful applications of loops use another LLM as a judge or as an orchestrator." "The harness just needs some signal that lets it continue. It does not have to be objective or binary." He does not say that signal is good enough to merge lasting code. Huntley, 2026-11-11: the thing that stops a loop closing on bad output is "deterministic checks," and he separates those from skills. A chapter title on his 2026-10-13 page is "why LLM-as-judge isn't enough"; the page opened here is an outline, not the argument, so the title is not a finding. — [Coming Loop](https://lucumr.pocoo.org/2026/6/23/the-coming-loop/), [answer](https://ghuntley.com/answer/), [agency](https://ghuntley.com/agency/)

### Inferences
- "Subagents failed" is too coarse. The failure they keep reporting is a second writer with a partial copy of the task. A second process that only reads, or that only looks at the diff in a fresh context, is the version both Zechner and Cognition still use.
- Always-on coordinators fail in the stories where the coordinator is also allowed to invent the next task (Astra factory, Yegge's game outrunning its players, OpenAI's Friday slop hour). They are tolerated where a human or a test still picks the next unit (Ralph's one item, MiniJinja's failing snapshot, Hashimoto's one background agent).
- Instruction-file size is not the variable. OpenAI's 100-line map and Steinberger's 800-line scar log are both "kept." The failure mode OpenAI names is a file that cannot be checked and that crowds out the task. Steinberger's file is append-only notes of concrete misses, and he already deletes notes the model has absorbed.

### Gaps
- No first-party ablation of "role-play system prompt versus none" with a score, other than Zechner's unread Terminal-Bench image and the claim that frontier models are "RL-trained up the wazoo" so they do not need the native 10,000-token prompt.
- Yegge's later claim that Gas Town burned down on Opus 4.7 was not opened at the source. See the gap in the first section.
- Dex Horthy's "skill issue" post (2026-03-12, byline Kyle in the index) is mostly a taxonomy of harness configuration points and cites Viv and Anthropic's skills docs. It was not fully read. Do not treat it as a failed-experiment log. — [Skill Issue](https://www.humanlayer.dev/blog/skill-issue-harness-engineering-for-coding-agents)

## How do they keep a feature from taking half a day and a fortune in grader tokens?

### Takeaway
The builders who are trying to cap cost do it before the grader exists: one item per fresh context, a test or a linter as the oracle, and a human who stops the run when the blast radius is wrong. The lab that published the biggest throughput numbers did the opposite on purpose: agent review until the agents are satisfied, six-hour unattended runs, and they replaced a human cleanup day with more agent cleanup. Nobody in this set published a diff-only re-review that is cheaper by a measured token factor, except Cognition's qualitative claim that a clean-context reviewer looking at the diff beats the author rereading its own trace.

### Cited Findings
- One item, fresh context. Huntley: "one task per loop," and the porting recipe is "just one thing and the most important thing per loop." The check that stops the loop is the compiler and the tests, which he now calls "back pressure," not a model. — [Ralph](https://ghuntley.com/ralph/), [porting](https://ghuntley.com/porting/), [answer](https://ghuntley.com/answer/)
- Zechner, 2025-11-30. Context gathering in a separate session that writes an artifact, then implementation in a fresh session, so the implementation context is not full of search junk. Review is another fresh pi, not a grader stuffed into the writer. MCP tool lists stay out of the always-on prompt; a CLI plus a README is read "only when necessary." He quotes the tax: 13.7k and 18k tokens, 7-9% of the window, before work starts. — [pi](https://www.mariozechner.at/posts/2025-11-30-pi-coding-agent/)
- Ronacher, MiniJinja. The grader is the snapshot suite. He did not run a model against the port to decide it was done. He queued "continue making all tests pass" and went to sleep only after the semantics he cared about were already steered. Branch-switch in pi shows him the summary that gets injected, which is his version of a context firewall. Cost of that choice: $60 and 34 prompts of his, against 2.2M tokens. — [MiniJinja port](https://lucumr.pocoo.org/2026/1/14/minijinja-go-port/)
- Ronacher, the counterexample, 2026-09-07. No oracle, subagents, notes the model edited with Python, 35 hours, about $1200, 79 commits he did not want. His rule after that: do not leave this class of model on one prompt. — [Astra](https://lucumr.pocoo.org/2026/9/7/astra-why/)
- Steinberger. "Blast radius": he will throw "many small bombs" or one large one, not several large ones, because isolated commits become impossible. "If something takes longer than I anticipated, I just hit escape." "Don't be afraid of stopping models mid-way, file changes are atomic." Tests: "ask the model to write tests after each feature/fix" in the same context, not a second model. He says a fresh context for the plan "would easily add 10 minutes" of the model rereading files, and he stopped doing that once he moved to GPT-5. UI work is under-specified on purpose and watched in the browser; "at least 50%" of prompts are a screenshot, which is a cheap way to point at the failure. `/review` is "only sometimes," because "I have review bots on GH." Refactoring is a separate phase, "~20% of my time," not a grader on every commit. — [just talk to it](https://steipete.me/posts/just-talk-to-it)
- Hashimoto. "The most sure-fire way" to a first-try result "is to give the agent fast, high quality tools to automatically tell it when it is wrong." He does not add a model grader. He also refuses to run agents "for the sake of running agents," and he turns off desktop notifications so the agent cannot interrupt him. One agent, checked on his breaks. — [Hashimoto](https://mitchellh.com/writing/my-ai-adoption-journey)
- Cognition, 2026-04-22, the diff-only argument, qualitative. The review agent "only look[s] at the diff, and re-discover[s] any context it needs" from a clean window, because the author has "been working for hours" and "context rot" makes it worse at judging its own work. They also say the loop "isn't always great since it can take a while." The author is then prompted to filter the reviewer's bugs against the user's instructions, which is how they try to stop the reviewer from inventing out-of-scope work. "Most bugs are already resolved by the time a human opens the PR." No token ratio for review versus generation in this post. — [Multi-Agents](https://cognition.com/blog/multi-agents-working)
- OpenAI, the lab that spends the grader tokens. Review is a Ralph loop of agents "until all agent reviewers are satisfied." Humans are optional. They made the app, DOM snapshots, screenshots, logs, metrics, and traces readable by Codex so a prompt such as "startup under 800ms" or "no span over two seconds in four core flows" is something the agent can check itself. Per-worktree app plus a per-worktree observability stack is the isolation. Custom linters carry the fix instruction in the error message, so the "grader" for architecture is a program. The human cleanup day (20% of the week) was the thing that did not scale; they replaced it with scheduled Codex refactor PRs, "most reviewable within a minute and auto-merged." Merge gates are mostly non-blocking; flaky tests are rerun rather than held. This is a choice to spend agent time instead of human time, including runs over six hours. It is not a recipe for cheap grader tokens. — [OpenAI](https://openai.com/zh-Hant-HK/index/harness-engineering/)
- Yegge, 2026-11-14 quoted notes. The cap he preaches is human pace, not a token budget. If the factory outruns the people around it, "everything starts breaking," including at the size of his game. — [quoted talk notes](https://x.com/AGTPinsights/status/2121732981975101767)
- Ronacher, 2026-10-06. Codemode keeps MCP schemas out of the prompt and runs orchestration in a WASM sandbox that cannot touch the user's files except by calling tools. That is a token and authority cap on tool definitions, not a review cap. — [Codemode](https://lucumr.pocoo.org/2026/10/6/codemode/)

### Inferences
- "Tests as the oracle" shows up as a real cost cap only when the tests already exist and the agent cannot edit the expected output without the human noticing. MiniJinja had that (Rust snapshots). OpenAI built the linters first, then let the agent run for hours. A feature without a pre-existing check falls into Steinberger's loop (human watches, escape if it runs long) or Ronacher's factory (it runs until someone pulls the plug).
- Diff-only re-review is argued, not priced, in this set. Cognition's reason is attention math, not a bill. Steinberger mostly does not re-review with a model at all.
- Small commits are Steinberger's isolation mechanism and OpenAI's throughput mechanism. They use them for opposite reasons: he wants to reset one bomb; they want PRs cheap enough that a wrong merge is cheaper than waiting.

### Gaps
- No source opened here gives grader-token cost per feature, or a measured saving from diff-only review versus full-trace review.
- No source gives a review-round cap that an individual builder enforces. OpenAI's loop is explicitly unbounded ("until satisfied"). Cognition says the review loop can "take a while" and does not give the cap.
- Huntley's $10.42 an hour, if Dex's worksheet were opened, would be the closest public cost-per-hour for a Ralph loop. The worksheet was not opened, and Huntley does not show the token log.
