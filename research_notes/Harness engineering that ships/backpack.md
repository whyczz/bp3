## What is spawned in each loop, and what context it reloads?

### Takeaway

Since 2026-11-22 the default loop is induct-inline: one main session authors every node, and each cycle spawns exactly one fresh grader whose whole prompt is the cold brief `bp3` renders. Full induct still exists for parallel nodes: the conductor authors nothing, and each ready node gets an `induct-node` workflow that spawns a new agent for the state read, the author, the grade, the verify, the cast, and the land. A heavier stacked grader (`induct-grade.js`, 1022 lines) is still installed and described in the conductor skill, but the ready-set path does not call it.

### Inferences

- A serial quest (each node depends on the last) cannot use the inline overlap: the skill waits for the grader when nothing else is ready. Cost is then author-session time plus one cold grade, in series, once per cycle.
- Full induct's token shape is "many fresh contexts per cycle," not "one deep grader." The preferred `induct-node` path pays an agent even to read state and even to type the cast command. The 1022-line stacked grader is a second, fallback shape that also reloads `code-reviewer` and `verify`. The skill text describes both as current, so a session that follows the ready-set paragraph and a session that follows the "inside induct-grade" paragraphs do not run the same agents.
- The inline grader reloads more reading than the `induct-node` grade child is prompted to do: pasted gates, full `GRADING.md`, `git show`, and an instruction to re-judge the gates in full. That is the cold start. It does not reload the author's chat, the author's rationale, or the previous `--reason`.

### Gaps

- No live run was watched, so which dispatcher a `/induct` session actually calls is inferred from the skill text plus the workflow source, not from a tape.
- Token cost of loading `code-writer`, `code-reviewer`, `verify`, `CLAUDE.md`, or `AGENTS.md` on every turn was not measured. Only line counts of the induct skills, `GRADING.md`, and `brief.ml` were taken.
- How large a rendered brief is, in tokens, for a real node was not measured. `Brief.render` output was not executed.

## Why would one quest take half a day?

### Takeaway

The written waits that stack are: a fresh grader every cycle, a full re-judge even when a diff is attached, up to 10 cycles before a human is asked, `make check-full` on every grade, a new worktree per grade, and a stop for the owner at the cap, on constraints, and at promotion. The one measured node that already blew past half a day is test-pyramid tier.1 at 14.3h wall, 9.4h of it sitting in `handed_off`. Model turns, not the shell gate, were most of a grade's wall in the later inline numbers.
